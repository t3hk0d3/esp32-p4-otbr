# ESP32-P4 OpenThread Border Router Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Firmware for the Waveshare ESP32-P4-WIFI6-POE-ETH that runs a standalone, HA-compatible Thread Border Router on Ethernet, using the on-board ESP32-C6 as an SPI radio, with sniffer mode, paired (P4 app + web) OTA, on-request streaming update of the separately distributed C6 RCP firmware, an optional maintenance jumper and CPU diagnostics.

> **R14 (2026-10-31):** the RCP firmware is no longer bundled with, stored on, or versioned by the P4. Completed tasks 5–10 are kept as the historical record; **Task 11B** reworks them. Where a task below conflicts with R14, R14 and Task 11B win.

**Architecture:** Three ESP-IDF projects in one repo: `p4/` (border router), `c6_rcp/` (radio firmware), `c6_updater/` (frozen C6 updater), plus a shared wire-protocol component. The P4 reuses upstream esp-thread-br's Web GUI/REST server and OTA component (vendored at a pinned commit with a tracked patch list); everything board- and feature-specific is ours.

**Tech Stack:** ESP-IDF v6.1, FreeRTOS SMP, OpenThread (ESP-IDF component), lwIP, esp_http_server, SPIFFS, esp-serial-flasher, Unity (host tests on the `linux` target), pytest-embedded (target tests), Python 3 tooling.

**Spec:** `docs/superpowers/specs/2026-10-30-esp32-p4-otbr-design.md` — read it before any task. Section references (§) below point into it.

## Global Constraints

- ESP-IDF **v6.1** for all three projects, recorded in `IDF_VERSION` at the repo root.
- esp-thread-br vendored from commit `1f5af46d0ccb22fe01465ba6d16a33b276c20c1b`.
- Every P4 build: `CONFIG_ESP32P4_SELECTS_REV_LESS_V3=y` (board has chip rev v1.3), `CONFIG_ESPTOOLPY_FLASHSIZE_32MB=y`, `CONFIG_SPIRAM=y`, `CONFIG_SPIRAM_XIP_FROM_PSRAM=y`, `CONFIG_OPENTHREAD_RADIO_SPINEL_SPI=y` (the web server is started by our `app_main`, R11, so `CONFIG_OPENTHREAD_BR_START_WEB` is not used; `esp_rcp_update` is gone, R14, so `CONFIG_AUTO_UPDATE_RCP` does not exist), raw link enabled through an OpenThread custom header (`CONFIG_OPENTHREAD_HEADER_CUSTOM=y`, `OPENTHREAD_CONFIG_LINK_RAW_ENABLE 1`).
- Never change lwIP options that alter `struct netif` (`CONFIG_LWIP_NUM_NETIF_CLIENT_DATA`, `CONFIG_LWIP_PPP_SUPPORT`, lwIP VLAN hooks / `ETHARP_SUPPORT_VLAN`): the prebuilt `libopenthread_br.a` depends on the layout. Keep `CONFIG_LWIP_PPP_SUPPORT=y`, `CONFIG_LWIP_NUM_NETIF_CLIENT_DATA=0`.
- RCP link: SPI2 at **10 MHz**, mode 0. Maintenance jumper pins: `JUMPER_RX` GPIO4, `JUMPER_TX` GPIO5, `JUMPER_BOOT` GPIO22.
- Never call `otLinkSetChannel()` with the raw link disabled (invalidates the datasets).
- esp-thread-br vendored from one `main` commit at or after 2026-10-13 ("feat(br_server): align Thread REST APIs with ot-br-posix 0.6.0"); commit hash recorded in `p4/components/PATCHES.md`.
- `espressif/esp_ot_cli_extension` `~2.0.0`; `espressif/mdns` pinned exactly to `1.14.1` (patch 13 and R31 depend on its internals); `espressif/esp-serial-flasher` pinned exactly. `esp_rcp_update` is **not** a dependency (R14; originally pinned `==1.7.0`, removed by Task 11B).
- Version strings: `<UTC build timestamp YYYYMMDDTHHMMSSZ>-<7-hex git hash>[-dirty]`, ≤ 30 chars (fits `esp_app_desc_t.version[32]`), for the P4 app and `c6_rcp`; the frozen updater's version is content-addressed, `base-<8 hex>` (`tools/base_version.cmake`). The only version comparison left is **string equality** of the C6 `updater_version` with the embedded base image version (never ordering); the P4 holds no expected RCP version (R14).
- Pins are compile-time constants (`p4/main/board.h`, `common/c6_board/c6_board.h`), never Kconfig.
- P4 partition layout exactly as spec §5.1; C6 layout exactly as spec §4.1 (4 MB-safe).
- Pairing invariant (R14): running `ota_N` uses `web_N`; `esp_ota_set_boot_partition(ota_M)` is the only OTA commit point. No RCP image is stored on the P4 (no `rcp_N` partitions); the RCP firmware is a separate artifact (`c6_rcp.bin`) streamed to the C6 on request through `/device/radio/firmware` (upload, or `?from_url=`), where the C6 updater's `END` is the only boot-slot switch.
- One long operation at a time: P4 OTA and RCP firmware push share one lock (409 otherwise).
- Our device endpoints live under `/device/`; errors there are JSON `{"error": "<code>", "detail": "<text>"}`.
- Ethernet IPv4/IPv6 stays up in every mode; only the OpenThread netif goes down for sniffing.
- Network modes `single` (default: one untagged interface, DHCPv4) and `split` (`mgmt` + `thread_bb`, at most one untagged, distinct VLAN IDs 1..4094); no forwarding between `mgmt` and anything else; network changes only via confirm-or-revert (5 min); console `net reset` in all builds (spec §5.13).
- Sniffer mode is never persisted; reboot always returns to BR mode.
- No authentication (non-goal); no auto-forming of a Thread network.
- Core pinning per spec §5.11: core 0 = network path, core 1 = management.
- Vendored code keeps upstream formatting; every change to it is listed in `p4/components/PATCHES.md`.
- Test-only console commands live in `p4/main/test_cmds.c` and are compiled only when `OTBR_TEST_BUILD` is defined (`tools/build_all.sh --test`); target tests run against test builds.
- Test gating policy (user decision 2026-10-31, revised): a task's own gate is host tests + a successful build only — no flashing and no on-board test runs inside tasks. Target (pytest) tests and any hardware steps in a task's text are still WRITTEN with the task but are not run there; the implementer reports them as "deferred to V<n>". All flashing and on-board runs happen in the dedicated verification tasks (V1 after Task 11B, V2 after Task 15, V3 after Task 20, Task 21 at the end), always with `--port /dev/ttyACM0` and the IDF environment active.
- No implementation code in this plan (repository rule); behaviour is defined by the BDD blocks, one test per effect.

## Review Focus

1. **Power loss or reset during OTA** (after `web_M` is written but before commit): the device must boot the previous pair `(ota, web)` unchanged. → Task 13 target test `test_ota_reset_before_commit_keeps_running_pair`.
2. **HTTP client disconnects mid-upload**: update aborts, boot partition unchanged, running pair untouched, next upload succeeds. → Task 13 target test `test_ota_client_disconnect_aborts_cleanly`.
3. **Mode change racing a REST write** (e.g. `PUT /node/dataset/active` while `/device/sniffer.pcap` starts): exactly one wins; no Thread write lands while in `SNIFFER`. → Task 14 target test `test_guard_rejects_dataset_write_during_sniffer_transition`.
4. **C6 reset or SPI glitch mid RCP firmware push**: the transfer aborts cleanly (upload) or retries from `BEGIN` up to 3 times (URL); the previous firmware always stays the boot slot unless `END` succeeded, never a half-written boot slot. → Task 11B host tests (`rcp_sync_push_firmware`) and Task 21 target test `test_firmware_upload_reset_mid_transfer_keeps_previous`.
5. **Ethernet link down at boot or flapping**: BR, web server and app-validity marking are unaffected by link state; BR init happens when an address appears and survives a later flap. → Task 10 target test `test_boot_without_link_marks_valid_and_starts_br_on_link_up`.

## Task 2: Wire protocol (`common/rcp_sync_proto`)

**Files:**
- Create: `common/rcp_sync_proto/{CMakeLists.txt,include/rcp_sync_proto.h,rcp_sync_proto.c}`
- Test: `common/rcp_sync_proto/test_host/` (IDF project, `main/test_rcp_sync_proto.c`)

**Interfaces (Produces):**
- Constants: `RCP_SYNC_PROTO_MAGIC` (`0x5253`), `RCP_SYNC_PROTO_VERSION` (`1`), `RCP_SYNC_PROTO_MAX_PAYLOAD` (`4096`), `RCP_SYNC_PROTO_HEADER_LEN` (`6`), `RCP_SYNC_PROTO_CRC_LEN` (`4`), `RCP_SYNC_PROTO_VERSION_STR_LEN` (`32`).
- `typedef enum { RCP_SYNC_MSG_HELLO = 1, RCP_SYNC_MSG_BEGIN, RCP_SYNC_MSG_DATA, RCP_SYNC_MSG_END, RCP_SYNC_MSG_OK = 0x80, RCP_SYNC_MSG_ERR, RCP_SYNC_MSG_NAK } rcp_sync_msg_t;`
- `typedef struct { uint8_t type; uint8_t seq; uint16_t len; const uint8_t *payload; } rcp_sync_proto_frame_t;`
- `esp_err_t rcp_sync_proto_encode(const rcp_sync_proto_frame_t *frame, uint8_t *buf, size_t cap, size_t *out_len);`
- `esp_err_t rcp_sync_proto_decode(const uint8_t *buf, size_t len, rcp_sync_proto_frame_t *out);` (payload points into `buf`)
- Payload codecs (all little-endian, fixed layout):
  - `rcp_sync_hello_reply_t { uint16_t proto_version; char updater_version[32]; char boot_slot_version[32]; char other_slot_version[32]; uint32_t slot_size; }` with `rcp_sync_proto_put_hello_reply()` / `rcp_sync_proto_get_hello_reply()`
  - `BEGIN` payload: `uint32_t image_size`; `DATA` payload: `uint32_t offset` + bytes; `OK` payload for `DATA`: `uint32_t next_offset`; `ERR` payload: `uint16_t code` + `uint32_t expected_offset`
  - `typedef enum { RCP_SYNC_ERR_SIZE = 1, RCP_SYNC_ERR_OFFSET, RCP_SYNC_ERR_STATE, RCP_SYNC_ERR_FLASH, RCP_SYNC_ERR_VERIFY } rcp_sync_err_code_t;`
- CRC-32: ESP-IDF `esp_rom_crc32_le` on target; on the linux target use the same polynomial via a local table function selected at compile time (`CONFIG_IDF_TARGET_LINUX`).

**Behaviour:**

```
rcp_sync_proto
    encode/decode
        On valid frame
            - decodes type, seq and payload identical to the encoded input
        On CRC mismatch
            - returns ESP_ERR_INVALID_CRC
        On payload length > 4096
            - encode returns ESP_ERR_INVALID_SIZE
        On buffer shorter than header + len + crc
            - decode returns ESP_ERR_INVALID_SIZE
        On wrong magic
            - decode returns ESP_ERR_INVALID_RESPONSE
    hello reply codec
        On round trip
            - all fields equal, version strings NUL-terminated
        On version string of 31 chars
            - preserved exactly
```

  - `typedef struct { esp_err_t (*slot_version)(bool boot_slot, char *out, size_t len); esp_err_t (*begin)(uint32_t image_size); esp_err_t (*write)(uint32_t offset, const void *data, size_t len); esp_err_t (*finish)(void); uint32_t slot_size; } updater_flash_t;` — `slot_version` returns `ESP_ERR_NOT_FOUND` for an empty/unverifiable slot; `begin` erases the **inactive** slot; `finish` verifies and sets it as boot slot.
  - `void updater_core_init(updater_core_t *ctx, const updater_flash_t *flash, const char *updater_version);`
  - `esp_err_t updater_core_handle(updater_core_t *ctx, const uint8_t *req, size_t req_len, uint8_t *reply, size_t reply_cap, size_t *reply_len);`
- Produces (binary): `c6_updater` app with `PROJECT_VER` from `tools/version.cmake`; build also produces the C6 bootloader and partition table — together the **C6 base image**.

**Behaviour:**

```
c6_updater (updater_core)
    HELLO
        On boot slot with verifiable image
            - replies boot_slot_version equal to that image's PROJECT_VER
        On boot slot empty or unverifiable
            - replies empty boot_slot_version
        On any state
            - replies proto_version 1, updater_version, slot_size
    BEGIN
        On image_size within slot size
            - calls begin (erases the inactive slot)
            - replies OK
        On image_size larger than slot size
            - replies ERR(RCP_SYNC_ERR_SIZE) and does not erase
    DATA
        On offset equal to next expected offset
            - writes bytes to the inactive slot
            - replies OK(next_offset)
        On unexpected offset
            - replies ERR(RCP_SYNC_ERR_OFFSET, expected_offset) and writes nothing
        On DATA before BEGIN
            - replies ERR(RCP_SYNC_ERR_STATE)
        On repeated seq
            - replies the cached reply without writing
    END
        On image that verifies
            - calls finish (boot slot switched)
            - replies OK
        On image that fails verification
            - leaves boot slot unchanged
            - replies ERR(RCP_SYNC_ERR_VERIFY)
        On END with fewer bytes than image_size
            - replies ERR(RCP_SYNC_ERR_STATE)
    any request
        On CRC mismatch
            - replies NAK
```

Handshake (pseudocode for `updater_main.c`, the SPI-slave loop):

```
loop:
    queue SPI slave RX transaction (max frame size)
    pull INT low; wait for transaction done; release INT
    reply = updater_core_handle(request)
    queue SPI slave TX transaction with reply
    pull INT low; wait for transaction done; release INT
```

- Timeouts: HELLO 500 ms (3 tries), BEGIN 30 s, DATA 1 s, END 10 s; whole transfer retried up to 3 times from BEGIN.

Algorithm (pseudocode, `sync.c`):

```
rcp_sync_run:
    expected = image.expected_version()          # fail → FAILED_NO_FIRMWARE-style error, no transfer
    for attempt in 1..3:
        link.enter_updater()
        hello = HELLO (retry 3x)
        if hello failed: continue
        installed = hello.boot_slot_version
        if installed == expected: result UP_TO_DATE; break
        if transfer(image) ok:   result UPDATED;    break
    else:
        result = FAILED_PREVIOUS_FIRMWARE_PRESENT if last hello had non-empty boot_slot_version
                 else FAILED_NO_FIRMWARE
    link.release()                               # always

transfer:
    BEGIN(size); offset = 0
    while offset < size:
        DATA(offset, chunk ≤ 4096); on NAK resend same seq; on ERR(expected) → fail attempt
        offset = reply.next_offset
    END
```

**Behaviour:**

```
rcp_sync (P4)
    rcp_sync_run
        On C6 boot-slot version equal to expected
            - sends no BEGIN
            - returns UP_TO_DATE
        On C6 version different (older or newer)
            - pushes the paired RCP firmware to the C6
            - returns UPDATED
        On transfer reset mid-DATA
            - retries from BEGIN and returns UPDATED
        On NAK reply
            - resends the same seq
        On transfer failure on all 3 attempts with a valid C6 boot slot
            - returns FAILED_PREVIOUS_FIRMWARE_PRESENT with both versions
        On transfer failure with no valid C6 image
            - returns FAILED_NO_FIRMWARE
        On missing expected image in storage
            - returns FAILED_NO_FIRMWARE with last_error "no rcp image"
        On completion (any result)
            - releases the SPI bus
            - drives GPIO6 high
```

```
rcp_sync_push_firmware(source):
    attempts = 3 if source.reopen != NULL else 1
    for attempt in 1..attempts:
        if attempt > 1: source.reopen() ; fail → abort
        enter_updater; HELLO (retry 3x); validate size
        BEGIN(total_size); offset = 0
        while offset < total_size:
            DATA(offset, next chunk from source.read)   # per-frame NAK/timeout: resend same seq, same bytes
            on ERR(expected_offset) or retries exhausted: transfer failed
        END → success returns OK ; ERR(verify) → failure, no further attempts
    release; return the last error
```

- `ot_lock_wrap.c`: `__wrap_esp_openthread_lock_acquire` / `__wrap_esp_openthread_lock_release` record acquisitions, wait time, hold time, holder task; linked with `-Wl,--wrap=esp_openthread_lock_acquire -Wl,--wrap=esp_openthread_lock_release` in `diag/CMakeLists.txt` (`target_link_libraries(... Algorithm (pseudocode, `windows.c`):

```
on each sample:
    for each task (by handle_id): delta = runtime - prev_runtime (mod 2^32); new task → delta = runtime
    push per-task delta and per-core total delta into a 60-slot ring
    cpu_pct[w] = sum(task deltas over last w slots) / sum(core totals over last w slots of the task's core) * 100
      (unpinned tasks: divide by the sum over both cores)
    load_pct[core][w] = 100 - idle_task_of_core cpu_pct[w]
    drop tasks not seen in this sample
```

**Behaviour:**

```

    sampler (windows)
        On each 1 s tick
            - updates per-task cpu_pct for the 1 s, 10 s and 60 s windows
            - per-core load_pct equals 100 minus that core's idle-task share
        On runtime counter wrap
            - delta is computed modulo 2^32
        On task created since the previous tick
            - includes it with cpu_pct computed from its runtime since creation
        On task deleted since the previous tick
            - removes it from the snapshot
    OpenThread lock wrapper
        On acquire followed by release
            - increments acquisitions
            - updates max_hold_us when the hold time exceeds the previous maximum
        On acquire that waits
            - updates max_wait_us
device_api
    GET /device/diag
        On any mode
            - returns 200 with cpu, tasks, memory and ot_lock sections
            - does not call uxTaskGetSystemState in the request path
```

```
            - frames with an unknown VLAN ID are dropped
            - the OpenThread backbone netif is thread_bb
            - the mDNS hostname answers on both interfaces; _meshcop._udp only on thread_bb
    isolation (split mode)
        On packet arriving on mgmt not addressed to the device
            - is dropped, not forwarded
        On packet from thread_bb or Thread whose route resolves to mgmt
            - is dropped, not forwarded
        On reply to an off-subnet management client
            - leaves via mgmt
    request policy (split mode)
        On /device/* or Web GUI request arriving on mgmt
            - is allowed
        On /device/* or Web GUI request arriving on thread_bb
            - returns 403 and closes the connection
        On PUT /node/dataset/active arriving on mgmt
            - returns 403
        On GET /node/state arriving on mgmt
            - is allowed
        On any /node/* or /api/* request arriving on thread_bb
            - is allowed
    request policy (single mode)
        On any request
            - is allowed
    confirm-or-revert
        On PUT /device/network with valid config
            - stores it as pending trial and reboots into it
        On PUT /device/network with invalid config
            - returns 400 naming the field and stores nothing
        On POST /device/network/confirm on the trial's management interface within 5 min
            - makes the trial the active config
        On POST /device/network/confirm on the wrong interface
            - returns 403 and the trial stays pending
        On no confirm within 5 min
            - reboots into the previous active config
        On reset during the trial
            - next boot uses the previous active config
        On console "net reset"
            - restores defaults (single, untagged, DHCPv4) and reboots
```

## Follow-ups (not in this plan)

- **Seamless C6 radio updates** (requested 2026-10-31, deferred). Current design: BR stops during the push (~2.3 s transfer measured in Phase 0 plus C6 reboot and OpenThread restart), streaming from the client as the data arrives. Candidate improvements, in order of cost:
  1. Buffer the radio image in PSRAM (RAM only, nothing stored on flash) and validate its header before stopping the BR, so the outage is a constant ~3–5 s independent of client speed and a bad or stalled upload never touches the BR; failed pushes retry from the buffer for body uploads too. Plus a fast restart path reusing the stored dataset.
  2. Zero-interruption update over the Spinel link: a vendor command in `c6_rcp` writes the inactive C6 slot while OpenThread keeps running, then one C6 reboot with RCP restoration (~1 s gap). Needs a `c6_rcp` source change, flash writes while the radio is live, and cannot update units whose installed RCP lacks the command (updater path remains the fallback).
