# USB/IP server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A USB/IP server that exports whatever device is on the board's USB-A port, as bus id `1-1` on TCP 3240, to
one Linux or Windows client, as a boot-time alternative owner of the USB port next to `radio_mux`.

**Architecture:**
- A new component `usbip` owns the USB host when enabled. Its logic is pure and host-tested: the wire codec
  (`proto.c`), descriptors and decision tables (`core.c`), the memory budget (`budget.c`), and the session engine
  (`engine.c`, over an ops seam onto esp-usb).
- The esp-usb side (`usb_side.c`) and the socket side (`net.c`) are thin target-only glue. A settings and boot module
  (`usbip.c`) holds the NVS flag and the public API.
- `radio_mux` learns that the USB port can belong to someone else: it skips its USB transport, lists stored USB channels
  as unavailable with a reason, and refuses mode changes on them.
- `netcfg` gets a `NETCFG_SVC_USBIP` service. `device_api` serves `/device/usbip`. The web UI gets a USB/IP page.

**Tech stack:** ESP-IDF v6.1 (C, FreeRTOS) on the ESP32-P4, esp-usb 1.6.0 (`espressif/usb`). Host tests use Unity on
the ESP-IDF `linux` target. Target tests use pytest-embedded. Page tests use pytest + node (`tools/tests`).

**Spec:** `docs/superpowers/specs/2026-11-10-usbip-design.md` (approved by the user, b1a6f45). The section numbers (§)
below refer to it. The behaviour contract is its §14; this plan's BDD skeleton refines it per module.

## Review Focus

The input classes the spec implies but no single happy-path test exercises, with the test that pins each one:

1. **A client queues more reads than the budget on one endpoint while another endpoint must still move** (btusb: event
   and ACL reads always pending, HCI command on EP0 and bulk OUT). Expected: the OUT and the EP0 transfers still go
   out. Pinned in Task 6: "Budget full of IN reads on 0x81: a bulk OUT on 0x02 is still submitted".
2. **An UNLINK for a transfer that still waits in a PSRAM FIFO, or that completes while the unlink is handled.**
   Expected: exactly one answer per seqnum, never both a RET_SUBMIT and a RET_UNLINK -ECONNRESET. Pinned in Task 6:
   "Unlink of a waiting transfer" and "Completion arrives after the flush began".
3. **The device is unplugged mid-transfer, with transfers in flight and waiting.** Expected: the session ends, every
   buffer is freed (in-flight and waiting both 0), and the device is exported again when it returns. Pinned in Task 6:
   "Device gone with transfers in flight: all buffers freed".
4. **A client that connects and sends nothing, or a browser's HTTP request on 3240.** Expected: closed without a reply
   after 10 s or at the first byte, counted as refused, and a running session is untouched. Pinned in Task 4 (first
   byte rule) and in Task 12 (target test).
5. **USB/IP stored on while a USB channel's stored mode is `otbr` at boot** (NVS restore, or a race with the enable
   check). Expected: Thread runs, `state` is `blocked` with the channel id. Pinned in Task 4: "Boot decision: enabled
   with a held USB stack: blocked".

## BDD skeleton

The contract per module. Every effect is one test, grouped by scenario. The behaviour that crosses modules is §14 of the
spec; it is covered by the engine (Task 6), the JSON (Task 10) and the target tests (Task 12).

```
netcfg_policy
    netcfg_policy_allows(svc = USBIP)
        In single mode
            - allows the single interface
        In split mode
            - allows mgmt
            - refuses thread
    netcfg_policy_conn_allowed(svc = USBIP)
        On a mesh address
            - refuses in every mode

radio_mux_core
    radio_mux_usb_external_refuses
        On a USB channel with the port external and a mode change
            - returns true
        On a USB channel with the port external and only line or proxy settings
            - returns false
        On the built-in channel
            - returns false
        With the port not external
            - returns false

radio_mux
    radio_mux_set_usb_external (before radio_mux_start)
        On a USB channel's load and at every refresh
            - eff_mode is unavailable, state idle, reason RADIO_MUX_USB_EXTERNAL_REASON
        At start
            - usb_transport_start is not called
        After radio_mux_start
            - returns ESP_ERR_INVALID_STATE
    radio_mux_set
        On a USB channel with a mode while external
            - returns RADIO_MUX_REFUSE_USB_EXTERNAL and stores nothing
    radio_mux_stored_usb_stack
        When a stored USB channel has otbr or ziggurat
            - returns true with its id and mode
        When none has
            - returns false
        Before radio_mux_start
            - reads NVS and gives the same answer

channels_json
    verdict reply
        On RADIO_MUX_REFUSE_USB_EXTERNAL
            - 409 usbip_enabled with the fixed detail
    GET body
        - "usbip" is true while the port is external, false otherwise

usbip_proto
    usbip_proto_parse_op_header
        On version 0x0111 and a known code
            - returns ESP_OK with the code
        On another version
            - returns ESP_ERR_INVALID_VERSION
    usbip_proto_encode_devlist
        With a device
            - writes one 312-byte record and one 4-byte record per interface, big-endian
        Without a device
            - writes a header with zero devices
    usbip_proto_encode_import_reply
        On status 0
            - writes the header and the 312-byte record
        On another status
            - writes the header only
    usbip_proto_parse_cmd
        On CMD_SUBMIT
            - fills every field, big-endian, setup bytes as sent
        On CMD_UNLINK
            - fills the unlink seqnum
        On another command
            - returns ESP_ERR_INVALID_ARG
    usbip_proto_encode_ret_submit / usbip_proto_encode_ret_unlink
        - write a 48-byte header with the command, seqnum and status
    usbip_proto_first_byte_ok
        On 0x01
            - returns true
        On any letter or 0x00
            - returns false

usbip_core
    usbip_core_dev_record
        On a plain device
            - fills ids, class, speed, bConfigurationValue, interfaces from the raw descriptors
        On a hub (device class 9, or an interface of class 9)
            - returns ESP_ERR_NOT_SUPPORTED, why "hubs are not supported"
        On more than 15 endpoints over the interfaces' alt 0
            - returns ESP_ERR_NOT_SUPPORTED, why names the count
        On a truncated configuration descriptor
            - returns ESP_ERR_INVALID_SIZE
    usbip_core_endpoints
        - lists address, type and max packet size of one interface's alternate setting
        - lists nothing for an unknown interface or alt
    usbip_core_classify_setup
        - SET_CONFIGURATION to the active value: USBIP_REQ_SET_CONFIG_SAME
        - SET_CONFIGURATION to another value: USBIP_REQ_SET_CONFIG_OTHER
        - SET_INTERFACE: USBIP_REQ_SET_INTERFACE
        - CLEAR_FEATURE(ENDPOINT_HALT): USBIP_REQ_CLEAR_HALT
        - SET_ADDRESS: USBIP_REQ_SET_ADDRESS
        - SET_FEATURE(PORT_RESET) to a port (bmRequestType 0x23): USBIP_REQ_PORT_RESET
        - anything else, class and vendor requests included: USBIP_REQ_FORWARD
    usbip_core_status_errno
        - COMPLETED: 0; short IN with URB_SHORT_NOT_OK: -EREMOTEIO
        - STALL: -EPIPE; OVERFLOW: -EOVERFLOW; ERROR: -EPROTO; NO_DEVICE: -ENODEV
    usbip_core_check_submit
        - transfer above 16384, or control data above 4096: -EINVAL
        - isochronous or unclaimed endpoint: -EINVAL
        - wrong devid: -ENODEV
        - otherwise: 0
    usbip_core_check_enable
        - same as stored: USBIP_SET_NOOP
        - enable with a held USB stack: USBIP_SET_REFUSE_IN_USE
        - enable during a long operation: USBIP_SET_REFUSE_BUSY
        - enable otherwise, or disable: USBIP_SET_REBOOT
    usbip_core_boot_state
        - disabled: USBIP_STATE_OFF
        - enabled with a held USB stack: USBIP_STATE_BLOCKED
        - enabled otherwise: USBIP_STATE_NO_DEVICE

usbip_budget
    usbip_budget_grant
        On an endpoint with nothing in flight
            - grants, also with the shared budget used up
        On an IN endpoint with transfers in flight
            - grants while in-flight bytes + n <= 32768 and transfers < 32
            - refuses beyond
        On an OUT endpoint with a transfer in flight
            - refuses
    usbip_budget_release
        - frees the bytes and the endpoint's count; peaks are kept
    usbip_budget_wait_add
        - accepts while waiting bytes <= 1048576, refuses beyond
    usbip_budget_stats
        - reports in-flight and waiting bytes and their peaks

usbip_engine
    (behaviour: spec §14 "usbip (transfers)" and "on session end"; one test per effect there, plus:)
    on budget pressure
        - a waiting transfer goes out when its endpoint frees, before other endpoints' waiting transfers
        - waiting transfers of one endpoint go out in arrival order
    on device gone
        - every in-flight and waiting buffer is freed; budget stats read 0
    on completion during an unlink's flush
        - each seqnum gets exactly one answer

usbip (settings and boot)
    usbip_boot
        - per usbip_core_boot_state; when active, calls radio_mux_set_usb_external before radio_mux_start
    usbip_set_enabled
        - stores per usbip_core_check_enable and reports whether to reboot
    usbip_kick
        - ends the session if one runs; ESP_OK in any case

usbip_json
    usbip_json_status
        - writes every field of §9 in order; device and client null when absent
        - returns ESP_ERR_INVALID_SIZE when it does not fit

usbip page (usbip.js)
    UsbipLogic.view(status)
        - per state: chip text and class, whether the device, client, counters and attach boxes show
        - attach commands carry the board's address
    UsbipPage toggle
        - asks for confirmation before the PUT; on 409 usb_channel_in_use shows the detail and the Radios link
radios page (radios.js)
    while "usbip" is true
        - USB rows show the reason with a link to /usbip.html; the mode selector is disabled
```
