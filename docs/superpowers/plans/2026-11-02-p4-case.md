# ESP32-P4 board case (CAD model): implementation plan

> **Historical.** This is the plan the first version was built from. The design has moved on since (print feedback and
> a design review); the current design is the spec, `docs/superpowers/specs/2026-11-02-p4-case-design.md`, and the
> model in `case/`.

## Context

You approved the spec `docs/superpowers/specs/2026-11-02-p4-case-design.md` on branch `worktree-p4-case` (worktree
`.claude/worktrees/p4-case`). It describes a two-part FDM case for the Waveshare ESP32-P4-WIFI6-POE-ETH board:

- **Base:** one part with a flat back plate, all four walls, four standoffs with countersunk M2.5 holes from the back,
  and two L-keyholes.
- **Lid:** a honeycomb grille that clicks onto four wedged corner tabs.

This plan turns the spec into a parametric build123d model:

- STL and STEP outputs;
- automated fit and printability checks against the vendor STEP;
- `make case` and `make case-test`;
- a docs page.

Nothing is printed by me. The physical test print is yours, after review.

**Execution:** native in this session, step by step (no subagent-driven development). Each step is test-first: write the
tests from the BDD skeleton, see them fail, implement, see them pass, then commit. One whole-branch review at the end.

## Styleguide

`STYLEGUIDE.md` applies: Python is linted and formatted with `ruff` (via `make lint` / pre-commit), names are
`snake_case`, routine tasks go through the Makefile with a `## ` help comment, and docs live in `docs/`, one file per
topic.

Step 1 adds a short **"Case model"** section to `STYLEGUIDE.md`. Every later step follows it:

- **Layout:**
  - Code lives in the package `case/p4_case/`.
  - Tests live in `case/tests/test_<module>.py`.
  - `case/sketches/` is throwaway and is not imported by the model.
- **Coordinates:**
  - Everything is in the spec's **board frame**: X 0–55 (button edge at 0), Y 0–68 (cable edge at 0), and Z = 0 at the
    PCB's top face.
  - Case heights use `CASE_Z = board Z + 8.6`, through one named offset.
- **Constants:**
  - Every dimension in the spec is a named, upper-case constant in `p4_case/params.py`, with the spec section in a
    comment.
  - Board facts are constants in `p4_case/board.py` and are checked against the STEP model at test time.
  - No magic numbers in geometry code.
- **Functions:**
  - Geometry builders are pure: `build_*(…) -> Part`. No file I/O except in `build.py` and `board.load_board`.
  - Checks return a `CheckResult(name, ok, detail)` and never raise for a failed check. They raise only for bad input,
    such as a missing STEP file.
- **Tests:**
  - pytest classes named after the scenario, with the docstring `"<module>.<function>: <scenario>"`.
  - One test method per effect, named `test_<effect>`. This is the same pattern as `tools/tests/`.
- **Dependencies:**
  - Run through `uv` with pinned versions in one place, the Makefile variable `CASE_PY`.
  - Nothing is installed globally.

## Global constraints

- **Python:** 3.12, because build123d/OCP wheels exist for it. Pinned deps: `build123d`, `trimesh`, `numpy`,
  `matplotlib`, `pytest`. The exact versions are chosen in step 1 and must be at least two weeks old.
- **Board model:**
  - Fetched by `tools/fetch_board_model.sh` into `.artifacts/board/` (already git-ignored), with the zip's sha256
    checked (`916430…8e11`).
  - It is never committed.
- **Outputs:** go to `dist/case/` (already git-ignored): `p4_case_base.{stl,step}`, `p4_case_lid.{stl,step}` and
  preview PNGs.
- **CI:** the case targets stay out of `make test`, CI and `make package` (spec section 7).
- **Commits:** each ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and the `Claude-Session` line.
- **Spec changes:** if a check in spec section 8 can't be met, I stop and report back instead of bending the geometry.
  In particular, I don't open up the cable-wall holes without asking.

## Design notes

**Package `case/p4_case/`:**

- `board.py`: board facts and the board model.
  - `load_board(step_path) -> BoardModel`: loads the STEP once and keeps:
    - `parts`, the named top-level children with their bounding boxes;
    - `mesh`, a trimesh of the whole board;
    - `envelope`, the column envelope below.
  - `measure(board) -> dict[str, BBox]`: derives the facts in spec section 3 from named parts, for example
    `USB_TPYPE-000`, `RJ45_HR911105A`, `SD1_ASM`, `SWITCHER-*` and `LED1_ASM`.
  - `check_facts(board) -> list[CheckResult]`: compares the measured facts with the constants, to 0.05 mm.
  - `ColumnEnvelope`: top and bottom height maps on a 0.25 mm grid. They come from dense surface sampling of the board
    mesh, the same method as the survey. It's the cheap, conservative stand-in for "the board's volume" in every
    clearance check. The `BOARD-1069` child holds the modules as one solid, so per-part bounding boxes alone would be
    far too coarse.
- `params.py`: every case dimension from the spec, as constants, plus small derived helpers (inner and outer outline,
  `case_z(board_z)`).
- `base.py`: `build_base() -> Part`. It's composed of private helpers, one per spec bullet: plate, walls with rebate,
  cable-wall openings and thumb scoop, header slot, button pin-holes and recess, SMA D-hole, ribbon-plug recesses, tab
  dents, standoffs with countersunk through-holes, and keyholes.
- `lid.py`: `build_lid() -> Part`, with these helpers: stepped plate (flange and body), frame, honeycomb with the LED
  cells and cross rib, and four corner tabs. Each tab has a root fillet, an inner-face taper, outer and end-face lead-ins,
  and a detent bump.
- `checks.py`: one public function per bullet in spec section 8, each returning `CheckResult`. `run_all(board, base, lid)`
  returns them all.
- `build.py`: the CLI, `python -m p4_case.build --board <stp> --out <dir> [--check]`. It writes STL and STEP files and
  previews, prints a check table, and exits non-zero when a check fails.
- `render.py`: preview PNGs. These are orthographic depth-shaded views from trimesh ray casts (front, back, both ends,
  one side, and the assembled case with the lid lifted). They're drawn with matplotlib, so no GUI or OpenGL is needed.

**Reused:** the throwaway survey method (surface sampling into height maps) becomes `ColumnEnvelope`. The repo's
`tools/tests` conventions (class per scenario, `importlib` not needed since `p4_case` is a package on `PYTHONPATH`).

**Shapes:**

- `CheckResult(name: str, ok: bool, detail: str)`.
- `BBox(x0, x1, y0, y1, z0, z1)` in the board frame.
- `ColumnEnvelope`:
  - `top(x, y)` and `bottom(x, y)`, which return NaN where the board has no material;
  - `free_height_above_plate(region)`, the minimum gap between the back plate and the board's underside over a region.

**Tricky algorithms (pseudocode):**

Column clearance of a printed part against the board:

```
for each grid cell (x, y) inside the board outline ± 1 mm:
    intervals = vertical material intervals of the part at (x, y)        # trimesh ray cast up through the part
    board_span = [bottom(x,y) - CLR, top(x,y) + CLR] if board present else none
    for each interval overlapping board_span:
        if (x, y) is inside an allowed-contact zone (standoff ring, screw bore): continue
        record violation (x, y, overlap)
ok = no violations; detail = worst overlap and its location
```

Fitting motion (spec section 8):

```
bodies = PCB slab + bounding boxes of USB, RJ45, SD, header, buttons, plus a ribbon-free header box
pivot = line along X at (Y = 0, Z = -1.6)               # bottom edge at the cable end
theta0 = smallest angle at which every point of bodies rotated about pivot is above the wall tops on the header side
for theta from theta0 down to 0 step 1°:
    rotated = bodies rotated by theta about pivot
    if rotated ∩ base has volume > 0.01 mm³: fail at theta
ok = no failure; detail reports theta0
```

Printability:

```
mesh = part in print orientation (base: plate down; lid: top face down), lowest z = 0
down = faces whose normal points down more than 45° from horizontal and whose z > 0.05
group down into connected horizontal regions
for each region:
    if region is horizontal and its narrow span ≤ 18 mm and both ends rest on material: bridge, ok
    else: violation
```

Opening size (lid cells, header slot): offset each opening's 2D outline inward by 1.76 mm. If anything remains, the
opening is wider than 3.5 mm.

## BDD skeleton

```
tools/fetch_board_model.sh
    run
        With no cached zip
            - downloads the zip into .artifacts/board/
            - extracts the STEP as .artifacts/board/board.stp
            - exits 0
        With a cached zip whose sha256 matches
            - does not download again
            - exits 0
        With a zip whose sha256 does not match
            - deletes the bad zip
            - prints the expected and actual hashes
            - exits non-zero

p4_case.board
    load_board
        On the vendor STEP
            - returns a BoardModel with the named parts
            - puts the PCB top face at Z 0 and the outline at X 0–55, Y 0–68
        On a missing file
            - raises FileNotFoundError naming `make case-board`
    measure
        On the vendor STEP
            - returns boxes for the USB stack, RJ45, microSD, both buttons, LED, header, transformer and capacitors
            - returns the four mounting-hole centres
    check_facts
        When the constants match the model
            - returns only passing results, one per fact
        When a constant is off by more than 0.05 mm
            - returns a failing result naming that fact and both values
    ColumnEnvelope
        On the vendor STEP
            - top at the USB stack is 16.0 ± 0.1
            - bottom under the 2-pin socket near (28, 57) is −4.9 ± 0.1
            - is NaN outside the board outline
        free_height_above_plate
            - is ≥ 4.5 mm at keyhole K1 and ≥ 3.0 mm at K2

p4_case.base.build_base
    On default parameters
        - returns one valid, watertight solid
        - has the outer size 60 × 73 × 27.6 mm (± 0.1)
        - has the rebate 1 mm deep and half a wall wide on all four walls
        - has the USB, RJ45 and microSD openings at the spec positions with the spec margins
        - leaves at least 1 mm of wall between the USB opening top and the rebate floor
        - has the header slot X 0.5–54.5 with 3.5 mm clear height under the lid underside, open into the rebate
        - has two Ø2.5 pin-holes on the plunger axes and the inner recess around the buttons
        - has the SMA D-hole (Ø6.5, flat 5.9) at board Y 52
        - has 1 mm ribbon-plug recesses at the header end, leaving 1 mm of wall
        - has four tab dents level with the lid bumps, with 45° upper and lower faces
        - has four Ø6 × 5 mm standoffs on the mounting-hole axes
        - has a Ø2.8 through-hole and a 90° countersink for an M2.5 flat head under each standoff, 0.2 mm below flush
        - has two L-keyholes at (10, 42) and (42, 42): Ø8 entry, 4.3 × 7 mm arms toward +Y and +X
        - keeps the keyhole sweep areas free of other features

p4_case.lid.build_lid
    On default parameters
        - returns one valid, watertight solid
        - has a 1 mm flange that fits the rebate with 0.2 mm clearance per side, so the top is flush with the walls
        - has its underside at case Z 25.6
        - has a solid 5.5 mm frame, narrowed over the LED
        - has only openings of 3.5 mm or less, including the cells over the LED
        - has the cross rib near board Y 34
        - has four identical corner tabs 10 mm long and 3.5 mm deep, 0.2 mm from the side and end walls
        - tapers each tab's inner face from 2.4 mm to 1.9 mm
        - keeps each tab's wall-facing faces flat for 2 mm, then tapers them 0.5 mm to the tip
        - has a 1.5 mm root fillet on each tab
        - has a 0.4 mm detent bump with 30° ramps, 1 mm below the underside, on each tab's side-wall face

p4_case.checks
    board_clearance
        With the board in place and the default base or lid
            - passes with ≥ 0.3 mm clearance outside the allowed contacts
        With a part pushed 1 mm into the USB stack (test fixture)
            - fails and reports the location and overlap
    opening_paths
        On the default base
            - passes for USB-C, USB-A, RJ45, microSD, both buttons, header slot and SMA
        With an opening blocked (test fixture)
            - fails naming the opening
    fitting_motion
        On the default base
            - passes and reports the start angle
        With the USB opening's top cut 0.3 mm into the connector (test fixture)
            - fails and reports the first failing angle
    lid_clearance
        On the default lid with the board, SMA envelope, ribbon-plug block and ribbon path
            - passes
    ribbon_plug_fit
        On the default base
            - fits a 55.9 × 9 × 9 mm block on the header with ≥ 0.5 mm to the walls
            - leaves ≥ 1.3 mm between the block top and the lid underside
    keyhole_volumes
        On the default base
            - passes: both L-sweep head volumes (2.5 mm tall) are free of the board
    nut_circles
        On the vendor board
            - reports for each mounting hole whether a Ø6.5 × 2.5 mm circle on top is free; passes only if all four are
    opening_size
        On the default lid and base
            - passes: no lid opening and no header-slot gap is wider than 3.5 mm
        With a 4 mm cell (test fixture)
            - fails naming the opening
    watertight
        On both parts
            - passes for valid closed solids
    printability
        On the base (plate down) and the lid (top down)
            - passes: no overhang past 45° except bridges ≤ 18 mm
        With a 20 mm unsupported ledge (test fixture)
            - fails with the ledge's location and span
    run_all
        - returns one result per check above, plus the board-fact results

p4_case.build (CLI)
    main
        With a valid board path and an out dir
            - writes p4_case_base.stl/.step and p4_case_lid.stl/.step
            - writes the preview PNGs
            - prints one line per check
            - exits 0 when all checks pass
        With --check and a failing check
            - exits 1
        With a missing board file
            - prints the `make case-board` hint and exits 2
```

## Steps

1. **Scaffold and styleguide.**
   - Add the "Case model" section to `STYLEGUIDE.md`.
   - Create the package `case/p4_case/` and `case/tests/` with a `conftest.py`. It has a session-scoped `board` fixture
     loading `.artifacts/board/board.stp`, and `base` and `lid` fixtures.
   - Add `tools/fetch_board_model.sh`, with tests in `case/tests/test_fetch_board_model.py` that use a local file URL,
     not the network.
   - Makefile:
     - `CASE_PY ?= uv run --python 3.12 --no-project --with build123d==… --with trimesh==… …`;
     - targets `case-board`, `case` and `case-test`, each with `## ` help, added to `.PHONY`.
   - Commit.
2. **Board facts.**
   - `board.py`: `load_board`, `measure`, `check_facts`, `ColumnEnvelope`, and the constants from spec section 3.
   - Tests from the skeleton. Commit.
3. **Parameters and base.**
   - `params.py` and `base.py`, built up one spec bullet at a time, each bullet with its tests first.
   - Order: plate and walls and rebate, standoffs and countersunk holes, keyholes, cable-wall openings and scoop,
     header slot and ribbon recesses, buttons, SMA, dents.
   - Commit after the walls and after the openings.
4. **Lid.**
   - `lid.py`: plate and flange, frame and grille with LED cells and rib, then the corner tabs with fillet, tapers,
     lead-ins and bumps.
   - Tests first. Commit.
5. **Checks.**
   - `checks.py`, each check with its passing test on the real parts and its failing test on a small fixture part.
   - `run_all`.
   - If a check fails on the real parts, fix the geometry only where the spec leaves room. Otherwise stop and report
     back.
   - Commit.
6. **Build CLI and previews.**
   - `build.py` and `render.py`.
   - `make case` writes `dist/case/`, and `make case-test` runs pytest on `case/tests`.
   - Commit.
7. **Docs.**
   - `docs/case.md`:
     - what to print, and the print settings (PETG recommended, solid infill on the lid, no supports, orientations);
     - parts: M2.5 × 12 flat-head screws and nuts, wall screws 3.5–4 mm with pan heads ≤ Ø7.5 × 2.5 mm, SMA bulkhead
       and pigtail;
     - the assembly steps from spec section 6;
     - how to hang the case either way, and the keyhole spacing;
     - the make targets.
   - Index the page in `docs/README.md`, add `case/` to the layout in `docs/development.md`, and add a CHANGELOG
     `Unreleased / Added` entry.
   - Commit.
8. **Whole-branch review.** A fresh reviewer, at the end. Then fixes, and a final `make lint` and `make case-test`.

## Verification

- `make case-board`: downloads and verifies the STEP. Run once, then cached.
- `make case-test`: every test passes. The output lists each spec section 8 check as passing.
- `make case`: writes the four model files and the previews. I look at the previews: the assembled view, the lid lifted,
  and both ends.
- `make lint`: clean (ruff on `case/`).
- `uv run … python -m p4_case.build --check` exits 0.
- Your physical check (spec section 8): print both parts, fit the board, plug every connector, press both buttons with a
  pencil, insert and eject a card, fit and remove the lid, and hang the case both ways.
