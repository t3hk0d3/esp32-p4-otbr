# Docs and home page refresh for v0.6.0

Goal: the home page, the README (the site's Overview page) and the guide pages present everything that shipped in
v0.5.0 and v0.6.0, with no stale claims left.

Styleguide: `STYLEGUIDE.md`, section "Commands and docs" (guide vs reference pages, release-first, the words
"radio" / "Thread channel" / "Zigbee channel", glossary links at first use, diagrams from `tools/docs_diagrams.py` in
the `hero.svg` style). The home page keeps its current voice: short, non-technical sentences.

BDD skeleton: skipped. This is a documentation-only change, with no behaviour to test. The check is the docs build and
a visual pass.

## What is wrong today

Survey on master b2979cb (v0.6.0):

- **Stale claim, in three places:** "Thread and the on-board Zigbee coordinator run one at a time" appears in the home
  page's radios section (a visible note plus the diagram's `aria-label`) and in `docs/images/radios.svg` (its caption
  and `aria-label`, generated by `tools/docs_diagrams.py`). Since v0.6.0 they run together, one per radio.
- **Home page "New" strip** lists the v0.5.0 features (USB dongles, Zigbee, live moves, one-click updates). It has
  nothing from v0.6.0.
- **Home page tiles:** the "Room to grow" tile doesn't mention USB/IP or logging. The "Get started" text says "press
  Install", but the flasher now starts with **Detect board**.
- **README "Why" list:** nothing on Thread and Zigbee together, USB/IP, logging (syslog, live log), time sync, or
  support for newer P4 chips. The comparison table's "Second radio" row and the "Get started" step 1 predate them.
- **`docs/web-ui.md`:** the menu table has no **USB/IP** row (the page sits under Device, after Radios). The Dashboard
  section doesn't mention the warning shown when Thread and Zigbee share an 802.15.4 channel.
- **`docs/glossary.md`:** no entries for USB/IP or for firmware targets (board id, chip id, chip revision), which
  `updates.md`, `flash.md` and `first-install.md` use.
- **`docs/troubleshooting.md`:** "Known limitations" doesn't list USB/IP's lack of authentication, or that v3.1+
  chips have not been run yet. "Common problems" has no entry for the shared-channel warning.
- **`docs/README.md`** (the GitHub index): the Zigbee and Updates lines don't mention running beside Thread or
  per-chip files.

Already up to date (no change): `radios.md`, `zigbee.md`, `usbip.md`, `logging.md`, `networking.md` (Time, USB/IP),
`updates.md`, `flash.md`, `first-install.md`, `api.md`, `metrics.md`.

## Changes

1. **`tools/docs_diagrams.py` → `docs/images/radios.svg`**
   - Caption and `aria-label`: Thread and Zigbee run at the same time, one per radio, and a proxy runs beside either.
   - Regenerate the image with `tools/docs_diagrams.py docs/images`. Only `radios.svg` should change. Any other
     changed file means the generator has drifted, so stop and report it.

2. **`docs/overrides/home.html`, `docs/assets/home.css`**
   - Starting point: the uncommitted "advanced features" edits by the Remote GPIO port research session (branch
     `docs/home-advanced-features` in the main checkout, +103/-5, not yet reviewed by the user). They are taken into
     `docs/v060-refresh` as their own commit, and that session stops editing these files. The edits already do this:
     - Radios section: Thread and Zigbee "run side by side, one on each radio", in both the note and the
       `aria-label`. The "Zigbee too" tile adds "with Thread on the other radio".
     - "Room to grow" tile: a short list plus "See all of it ↓" to `#advanced`.
     - New `#advanced` section ("For power users", "Everything under the hood."): 12 linked cards in a 4x3 grid.
       USB/IP and Logging are tagged new. Time sync and the jumper are left out on purpose.
   - On top of them, in this plan:
     - "New" strip, with four links (the USB/IP and logging links go where their cards point):
       - Thread and Zigbee together → `zigbee/#thread-and-zigbee-together`
       - USB/IP → `usbip/`
       - Live logs and syslog → `logging/`
       - Firmware picked for your chip → `flash/`

       One-click updates drops off the strip; it has a card in `#advanced`.
     - Get started lede: "press Detect board, then Install: it picks the firmware for your chip".
     - The card grid stays at 12. Any addition swaps a card out rather than adding a 13th. Time sync stays out.
   - No new screenshots. The four home `.webp` files stay as they are (see "Not in this plan").
   - No mention of Remote GPIO / header I/O anywhere: it has no approved design or firmware yet.

3. **`README.md`** (Overview page)
   - Intro paragraph about the USB port: also a USB/IP server.
   - "Why" list, new or changed bullets, each linking its guide. Where a home card's one-liner fits, the bullet uses
     the same words, so the home page and the Overview agree:
     - Thread and Zigbee at the same time on two radios, with the same-channel warning.
     - USB/IP server.
     - Logging: per-component levels, syslog, the live log in the browser.
     - Time sync from NTP. This goes into the "Built for your network" bullet.
     - The "Updates itself" bullet: each board gets the firmware built for its chip.
   - Comparison table, "Second radio" row: Thread and Zigbee at the same time.
   - Get started, step 1: the flasher detects the chip revision and picks the matching firmware.

4. **`docs/web-ui.md`**
   - Add the USB/IP row to the menu table, under Radios, linking `usbip.md`.
   - Dashboard, Zigbee bullet: the warning when both networks use the same 802.15.4 channel, linking
     `zigbee.md#thread-and-zigbee-together`.

5. **`docs/glossary.md`**
   - New entries, in alphabetical order:
     - **Chip revision**: the P4 silicon revision. It decides which firmware file fits, and v3.0 gets none.
     - **Firmware target** (`board_id` + `chip_id`).
     - **USB/IP**.
   - Link the new terms at their first use in `updates.md` and `flash.md`, as the styleguide requires.

6. **`docs/troubleshooting.md`**
   - Known limitations:
     - USB/IP has no login or encryption. This joins the "No login" bullet.
     - Chips of v3.1 and later are built for but not yet run on hardware. This joins the "Not yet run on hardware"
       bullet.
   - Common problems: "The Dashboard warns Thread and Zigbee share a channel", with what to do (move one network,
     linking `zigbee.md`).

7. **`docs/README.md`**: update the Zigbee and Updates index lines to match.
