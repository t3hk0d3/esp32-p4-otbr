# Time sync (NTP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The P4 sets its clock from NTP (custom server, else the DHCP lease's servers, else `pool.ntp.org`), shows the
state on the Ethernet page, and existing timestamps (Zigbee, radio firmware) show real dates.

**Architecture:**
- New component `p4/components/timesync`: pure rules (`rules.c`, host-tested) and a runtime (`timesync.c`) with its
  own small task that owns ESP-IDF's `esp_netif_sntp` client. lwIP-thread callbacks only record and notify the task.
- DHCP's NTP servers are captured with a linker wrap of lwIP's `dhcp_set_ntp_servers` (the project's existing
  `--wrap` pattern in `netcfg`), which also learns the interface from `ip_current_input_netif()`. SNTP's own DHCP
  mode stays off: the task always sets the servers itself from the rules.
- `device_api` gets `GET`/`PUT /device/time`; the Ethernet page gets a Time section (`time.js`); Zigbee records
  uptime and converts to epoch when read.

**Tech stack:** ESP-IDF v6.1 (C, FreeRTOS, lwIP SNTP) on the ESP32-P4. Host tests: Unity on the ESP-IDF `linux`
target. Page tests: pytest + node (`tools/tests`).

**Spec:** `docs/superpowers/specs/2026-11-10-time-sync-design.md` (approved 2026-11-10). § numbers refer to it.
Mockup: `docs/superpowers/specs/2026-11-10-time-sync-mockup.html`.

**Styleguide:** `STYLEGUIDE.md` (enforced by `make lint`). The plan follows it: `timesync_` prefix, `esp_err_t` returns
with `ESP_RETURN_ON_ERROR`, one `TAG` per file, host tests in `<component>/test_host/` named
`TEST_CASE("<scenario>: <effect>", "[timesync]")`, no lwIP calls from the OpenThread or esp_timer task. Layout copies
`p4/components/netnames` (rules in `rules.c` + private `timesync_rules.h`, linux build compiles only the rules).

## Global Constraints

- Valid clock: `time(NULL) >= 1577836800` (2020-01-01 00:00:00 UTC).
- Default server `pool.ntp.org`; at most 2 servers in use; DHCP servers beyond the first two are ignored.
- Custom server: 1 to 63 bytes; IPv4 literal, IPv6 literal, or hostname (labels of `a-z A-Z 0-9 -`, dot-separated,
  no label starting or ending with `-`). Empty only in `auto`.
- Defaults with nothing stored: `enabled` true, `mode` `auto`, `server` `""`.
- `waiting` turns into `unreachable` after 60 s without an answer.
- `PUT /device/time` body limit 256 bytes.
- sdkconfig: `CONFIG_LWIP_DHCP_GET_NTP_SRV=y`, `CONFIG_LWIP_DHCP_MAX_NTP_SERVERS=2`, `CONFIG_LWIP_SNTP_MAX_SERVERS=2`.
  `CONFIG_LWIP_MAX_SOCKETS` and `CONFIG_LOG_TIMESTAMP_SOURCE` unchanged.
- Board keeps UTC; no TZ setting. Log line timestamps untouched.
- Off means no NTP traffic: SNTP client stopped.
- No flashing inside tasks; one on-board pass after review and fixes (§8).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **DHCP renewal naming the same servers** (every T1, about half the lease): must not restart SNTP or drop
   `synced` back to `waiting`. Test in Task 1 (`servers unchanged`).
2. **Clock stepped by a sync** (first sync jumps decades): `synced_age_s` and Zigbee dates must stay sane, never
   negative. Ages are computed from uptime, not epoch. Test in Task 1 (`epoch at`, `age`).
3. **Custom hostname that never resolves** (typo, no DNS): the state must reach `unreachable` after 60 s, not stay
   `waiting` forever. Test in Task 1 (`derive state`).
4. **Save twice quickly, or save while a lease arrives:** the task serialises both; the last config wins, no crash.
   Covered by Task 2's single-owner task design; checked on board (§8 step 4).
5. **Split mode, both leases name servers:** the last lease wins, and `dhcp_iface` names that same lease, never a
   mix. Test in Task 1 (`dhcp capture`).

Design points the implementer can't infer:
- **One owner task** (`timesync`, small stack, low priority, pinned per `board_cores`) holds the SNTP client. It waits
  on task notification bits: `CONFIG_CHANGED`, `DHCP_CHANGED`, `ANSWERED`, plus a 10 s timeout for state upkeep. On
  `CONFIG_CHANGED` or `DHCP_CHANGED` it runs `timesync_rules_choose`; if `servers_equal` to what runs, nothing happens
  (Review Focus 1). Otherwise: `esp_netif_sntp_deinit()`, then (if any servers) `esp_netif_sntp_init()` with
  `server_from_dhcp = false`, `start = true`, `sync_cb` set, servers by name; reset `started_us` and
  `answered_since_start`.
- **lwIP-thread callbacks only record:** `sync_cb` stores `esp_timer_get_time()` as `last_sync_us` under a spinlock and
  notifies `ANSWERED`. The task then reads `esp_sntp_getreachability(i)` to pick `answered` and `any_reachable`.
- **`__wrap_dhcp_set_ntp_servers(u8_t num, const ip4_addr_t *servers)`** in `dhcp_wrap.c`: runs on lwIP's thread inside
  `dhcp_recv`; maps `ip_current_input_netif()` to an iface, calls `timesync_rules_dhcp_capture` under the spinlock,
  notifies `DHCP_CHANGED`, then calls `__real_dhcp_set_ntp_servers` (harmless: SNTP's DHCP mode is off). If the
  mapping yields no known netif, iface is `NONE` (spec §6.3: `dhcp_iface` null).
- **Lease lost:** register for `IP_EVENT_ETH_LOST_IP`; when the lost netif is the captured iface, clear the capture and
  notify `DHCP_CHANGED`. Check during implementation that netcfg's VLAN netifs post it (spec §6.4); if they don't,
  note it in the task report and leave the capture until the next lease.
- **`timesync_clock_valid`** is `time(NULL)` against the constant: no lock (logging contract).
- **Storage:** NVS namespace `timesync`, keys `en` (u8), `mode` (u8), `server` (str). `set_config` validates, writes,
  commits, then copies to the running config and notifies; a write failure returns the error with nothing changed.
- **`get_status`** copies under the spinlock and fills `now` (0 when not valid), `synced_age_s` via `rules_age_s`,
  `state` via `rules_state`.
