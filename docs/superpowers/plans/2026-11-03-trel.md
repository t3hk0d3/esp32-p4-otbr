# TREL: implementation plan

## Context

Spec: `docs/superpowers/specs/2026-11-03-trel-design.md` (approved 2026-11-03). Branch `claude/project-thread-ey29jx` from `master`.
The IDF port (`components/openthread/src/port/esp_openthread_trel.c`) is used as is; nothing is vendored or patched.

Execution: native, in one session. One whole-branch review at the end by a fresh reviewer.

**Styleguide:** `STYLEGUIDE.md`. astyle via `make lint`, `snake_case`, component prefixes, `esp_err_t` with
`ESP_RETURN_ON_ERROR`, host tests in `<component>/test_host/` named `"<scenario>: <effect>"`, board tests in
`p4/pytest/test_<feature>.py`.

## Global constraints

- No change to lwIP options that alter `struct netif`.
- Flash writes: only when the stored config actually changes.
- The TREL switch never triggers a reboot or a trial on its own.
- No flashing during the work; board tests run in the next batched hardware pass.
- Commits end with only the `Co-Authored-By` line.

## BDD skeleton

```
netcfg config (config.c)
    netcfg_from_json
        Body without "trel"                 - keeps trel from the base config (PUT) / true (stored config)
        "trel" not a boolean                - ESP_ERR_INVALID_ARG, bad_field "trel"
    netcfg_to_json
        Any config                          - writes "trel" at the top level
    netcfg_equal
        Configs differing only in trel      - false
    netcfg_diff_only_trel
        Only trel differs                   - true
        Equal configs                       - false
        Any interface or mode field differs - false

netcfg isolation (isolation.c)
    netcfg_ip6_udp_drop
        mgmt input, dport 12390             - drop
        mgmt input, other dport             - keep
        backbone or single input, 12390     - keep

netcfg runtime (netcfg.c)                      [target only]
    netcfg_set_trel
        Trial pending                       - ESP_ERR_INVALID_STATE, nothing stored
        Same value                          - ESP_OK, no NVS write
        New value                           - rewrites "active", ESP_OK
    netcfg_trel_enabled                     - active config's value

br_core (br_core.c)                            [target only]
    br_core_set_trel
        BR_RUNNING                          - otTrelSetEnabled under the lock
        Other modes                         - stored, applied at the next bring-up
    bring-up                                - applies netcfg_trel_enabled() before Thread is enabled
    br_core_get_trel                        - enabled, active, peers, counters, up to 8 peers; lock wait bounded

device_api (device_api.c)
    PUT /device/network
        Only trel differs                   - netcfg_set_trel + br_core_set_trel, 200 {"status":"applied"}
        Only trel differs, trial pending    - 409 busy
        Other fields differ                 - trial as today, trel included
    GET /device/network                     - "trel" in active and trial config
    GET /device/status                      - "trel" object

metrics_render (render.c)
    Valid cache with TREL                   - br_trel_* families with the spec's names and labels
    Cache invalid                           - TREL families left out like the other Thread families

ethernet.js (device page logic, node tests)
    Off/On pressed alone                    - PUTs the active config with trel flipped; no review, no trial banner
    Interface edits pending                 - the switch joins the pending changes; review table has a "TREL" row
    Status trel.active false, enabled true  - chip "Waiting for Thread", hint about Thread not running
    peers 0                                 - empty-state hint with avahi-browse
```

## Steps

1. **Build switch.** `p4/sdkconfig.defaults`: `CONFIG_OPENTHREAD_RADIO_TREL=y`, `CONFIG_OPENTHREAD_TREL_BUFFER_SIZE=20`.
   `br_core.c` `EVENTFD_COUNT` 5. `tools/tests/test_mdns_config.py` (or a new `test_trel_config.py`) asserts both
   options are in the generated `p4/build/config/sdkconfig.json` (catches the Kconfig dependency dropping them).
   `logrun make build`; record the app size delta in the commit message. Commit `build: enable TREL`.
2. **netcfg config + isolation.** Field, JSON, `netcfg_equal`, `netcfg_diff_only_trel`, `netcfg_ip6_udp_drop`, test
   first in `netcfg/test_host`. Wire the drop into `__wrap_lwip_hook_ip6_input` (parse the UDP header only when the
   IPv6 next header is UDP). `make test-host`. Commit.
3. **Runtime.** `netcfg_set_trel`, `netcfg_trel_enabled`; `br_core_set_trel`, `br_core_get_trel`, bring-up hook.
   `logrun make build`. Commit.
4. **API.** `network_put_handler` branch, GET fields, status JSON. Update `tools/tests` shape checks and
   `p4/pytest/test_device_api.py` / new `p4/pytest/test_trel.py` (toggle off/on live, no reboot; status fields; UDP
   12390 on `mgmt` not answered in split mode). Commit.
5. **Metrics.** Collector fields, renderer families, `test_host` cases, `test_metrics_format.py` catalogue. Commit.
6. **Web UI.** Card in `ethernet.html` per the mock (CSS only appended), logic in `ethernet.js`/`device_common.js`,
   node tests in `tools/tests/test_ethernet_page.py`. Make the peer table scroll inside `.table-wrap` at phone width.
   PATCHES.md patch 3 entry updated. `make test-tools`. Commit.
7. **Docs.** `docs/networking.md` TREL section (what it does, needs peers on the backbone link, `avahi-browse -rt
   _trel._udp`), `docs/api.md`, `docs/metrics.md`, screenshot `docs/images/ethernet-trel.png`, CHANGELOG Unreleased.
   Optional: IDF issue about the `EXAMPLE_CONNECT_*` Kconfig dependency. `make lint`. Commit.
8. **Review.** `make test`, `make build`, whole-branch review; fix Critical/Important findings test-first. Open the PR.

## Verification

- `logrun make test-host`, `make test-tools`, `make build`, `make lint`.
- Hardware (batched): `make test-target TEST=p4/pytest/test_trel.py`; with a second TREL BR on the LAN:
  `ot trel peers` lists it, `ot neighbor table` shows the link, Thread devices stay reachable; toggle off/on from the
  page with no reboot; SNIFFER enter/leave and back to BR_RUNNING with TREL re-enabled.
